What it costs, and is it the cheapest?

Honest answer: it's sensibly sized for a demo and already optimized once. It isn't the floor yet, and we have measured numbers for the next steps.

Already done

Prompt caching

83% of input tokens come from Bedrock's cache. Estimated cost per turn fell from $0.041 to $0.020, with the same latency and eval results.

No model where no judgment is needed

Editing a chip, saving, thumbs and metrics never call the model. A chip edit takes about 0.2 s.

Right-sized infrastructure

Single-node OpenSearch, ARM Fargate, public subnets with no NAT gateway.

Next savings, in order

  1. Route by task: Haiku by default, Sonnet for complex multi-need searches. The eval set guards quality when the model changes.
  2. Reuse GreatSchools' OpenSearch cluster instead of a separate domain (about $54 a month).
  3. Move sessions to DynamoDB, then switch to pay-per-use compute (Lambda or Bedrock AgentCore Runtime) and drop the always-on task and load balancer.
  4. Trim tool payloads: a turn sends about 11,000 tokens today.
At scale, for illustration: 1 million guided searches a year × 4 turns = 4 million turns. That's roughly $80k a year on Sonnet, about $34k on Haiku, and in between with routing. One million is about 2.5% of the 40 million families GreatSchools serves each year.

Can GreatSchools carry it forward?

Yes, by design. It uses their stack, their data format and their way of turning needs into search.

What we builtWhat GreatSchools does to take it over
AWS, us-east-1, OpenSearch: the same stack they runNothing new to learn
Needs catalog in agent/gs_agent/needs.py, matching their "needs → OpenSearch parameters" designPoint the field names at their real indexes
Data in the exact format of their sample documentsReplace the synthetic generator with their feeds; ingestion scripts stay
Guide content in one JSON fileSwap in their own articles, no code change
Model on Bedrock, with an eval setChange models safely, as the Sonnet vs Haiku run shows
HTTP/JSON API with a written contract (docs/contract.md)Call it from their Rails app or render its blocks
CDK, README, 12 decision records, unit + eval + live API testsUnderstand why each choice was made; verify every change
Metrics that match their KPIs (saves-to-searches, relevance, criteria per search)A/B test against today's search from day one
